# M2 前端联调

运行 `npm ci`、`npm run dev`。默认调用真实 API；将 `.env.local` 中的
`VITE_M2_MOCK=true` 可启用内存演示，包括榜单、任务进度、分析详情、案例保存与机会详情。
演示数据始终显示提示，不会在请求失败时自动替代真实数据。Mock 保存刷新后重置。

M1 请求继续使用 `VITE_API_BASE_URL`（默认 `/api/v1`），M2 使用
`VITE_M2_API_BASE_URL`（默认 `/api`），开发代理均指向 `API_PROXY_TARGET`。

## 待后端确认的接口约定

类型定义见 `src/m2.ts`。以下为前端当前使用的约定，需在后端就绪后联调：

- `GET /api/analysis`：直接返回 `Analysis[]`；列表每 3 秒轮询。
- `POST /api/analysis/create`：`{ symbol, timeframe: "1h" | "4h" | "24h" }`，返回完整任务。
- `GET /api/analysis/{id}`：返回 `Analysis`，进行中详情每 2 秒轮询。
  状态为 `pending/running/completed/failed`；progress 为 0–100。
- `POST /api/cases`：`{ analysis_id, rating: 1–5, tags: string[], notes? }`。
- `GET /api/opportunities`：参数 `min_confidence`、`min_success_rate` 为 0–1，
  `hours` 为最近时间窗口，返回 `Opportunity[]`。
- `GET /api/opportunities/{id}`：返回 `Opportunity`，包含当前和历史特征、阶段。
- `GET /api/cases/search?opportunity_id={id}`：返回 `Case[]`。

所有时间为 ISO 8601，概率为 0–1。K 线复用 M1 candles API 与 Lightweight Charts；
仅对可见 K 线范围内的阶段起点绘制标记，完整阶段仍显示在时间轴中。

24h 榜单保持 M1 实时快照。1h/4h 对快照中的合约查询最新小时 K 线并重新排序，
不是所有合约的全市场榜单；缺少完整窗口数据的合约不纳入榜单，页面显示范围说明。

## 验证

`npm run build`；`npm test`。`src/m2.test.tsx` 覆盖创建分析、评分保存、
保存失败重试、机会筛选与详情/相似案例请求以及窗口计算。
