# M2 前端联调

运行 `npm ci`、`npm run dev`。默认调用真实 API；`.env.local` 中设置
`VITE_M2_MOCK=true` 可启用内存演示，包括榜单、任务状态、分析详情、案例保存与机会详情。
演示数据始终显示提示，不会在请求失败时替代真实数据。Mock 保存刷新后重置。

M1 使用 `VITE_API_BASE_URL`（默认 `/api/v1`），M2 使用
`VITE_M2_API_BASE_URL`（默认 `/api`），开发代理均指向 `API_PROXY_TARGET`。

## 后端契约对齐

已核对 `ao/m2-backend/implementation` 的 `54613a4`（`docs/M2_API.md` 及模型）。
类型与适配函数见 `src/m2.ts`：

- 创建分析提交 `{symbol, start_time, end_time}`，按当前已结束的整分钟构造 1h/4h/24h 窗口。
- 任务无 progress 字段：只显示服务端状态，完成才显示 100%，不推测执行百分比。
- `result.stages` 映射中文阶段、evidence；转折点显示 kind/reason，不虚构价格。
- 案例保存提交 `{task_id, title, outcome}`。当前后端拒绝额外字段，真实模式禁用评分和标签并提示待支持；Mock 模式保留评分标签交互。
- 机会使用 symbol 标识，显示 observed_at、historical_success_rate、labeled_cases。
  null 成功率显示“未标注”，筛选最低成功率时排除这些项。
- 列表请求只提交支持的 `min_confidence` 和 `limit=1000`。
  成功率及时间范围在已返回的未过期候选中本地筛选，页面说明了此范围。
- 相似案例搜索提交 symbol、start_time、end_time（观察时间向下对齐分钟的前一小时），
  limit、min_similarity，不使用 opportunity_id。
- 当前特征调用 `/features/{symbol}`；历史案例展示 title、outcome、analysis 的阶段证据。
  后端未提供历史数值特征快照，不生成历史数值对照。

K 线复用 M1 candles API 与 Lightweight Charts；观察时间落在数据范围内或最新 K 线的
两分钟内时显示当前识别标记。历史阶段时间轴保留案例自己的时间，不当作当前市场阶段时间。
24h 榜单保持 M1 快照；1h/4h 对快照合约的小时 K 线重新排序，缺少完整窗口则不纳入。

## 后端缺口（54613a4）

当前分支源码尚无 `GET /api/analysis`、`GET /api/opportunities/{symbol}`，
前端保留这两个请求与明确的错误/重试提示，等待后端补齐。
创建成功的任务会加入本次会话缓存，并可直接通过 URL 的 id 查看详情；刷新后需列表接口。
机会详情请求失败仍可基于已经读取的列表记录加载特征及相似案例，错误仍可见。
评分和标签需 CaseRequest、数据库及 CaseResponse 增加字段后再开启真实模式。

## 验证

`npm run build`；`npm test -- --maxWorkers=1 --testTimeout=60000`。
`src/m2.test.tsx` 验证真实后端字段、整分钟窗口、保存请求、错误重试、
机会筛选与按时间范围搜索、null 成功率和涨跌幅计算。
